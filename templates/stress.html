WHY STRESS TESTING?

Robustness should be measured, not assumed.

Real lunar observations can differ because of viewing geometry, illumination, image scale, image quality and other acquisition conditions. A correspondence pipeline should therefore be evaluated under controlled changes.

TEST MATRIX

What can be challenged?

Each transformation isolates a different type of perturbation. The objective is to observe the behaviour of the correspondence pipeline under controlled conditions.

↻

ROTATION

Tests whether local features remain usable when the image orientation changes.

⤢

SCALE

Tests correspondence behaviour when the observation is enlarged or reduced.

◐

ILLUMINATION

Brightness and contrast changes simulate differences in image appearance.

≋

NOISE

Tests sensitivity to synthetic image noise.

◌

BLUR

Tests the effect of reduced high-frequency image detail.

⌗

CROP

Tests correspondence when only part of the original scene remains visible.

```
```
!
IMPORTANT

Synthetic robustness is not lunar ground truth.

The transformation is controlled by the test system, so its parameters can act as an experimental reference. This measures pipeline behaviour under known perturbations; it does not prove that the system has achieved a particular real-world lunar localization accuracy.

```
```
JUDGE QUESTION
ROBUSTNESS

“How do you know the model is robust?”

Instead of making an unsupported claim, LUNARMATCH provides a controlled experiment: start with an image, apply a known transformation, rerun correspondence, and compare measurable outputs.

01 CONTROL

The original image provides the baseline.

02 PERTURB

A known transformation is applied.

03 REPEAT

The same correspondence pipeline is executed again.

04 MEASURE

Score, verified matches and geometric behaviour are compared.
